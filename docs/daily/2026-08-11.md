## Goal

구현 전에 제품 경계, 데이터 흐름, 정합성 전략, API 초안과 측정 기준을 검토 가능한 문서로 고정한다.

## Completed

- 로컬 `spendguard` Git 저장소 초기화
- 제품 문제와 MVP 범위 정의
- 입력원별 역할 정의
- 모듈러 모놀리스와 API·Worker 실행 프로필 결정
- Raw Event → Outbox → Kafka → Worker → Ledger 흐름 정의
- Redis 없는 PostgreSQL 정합성 전략 ADR 작성
- append-only 원장과 취소·환불 모델 정의
- 초기 ERD 작성
- 초기 OpenAPI 3.1 계약 작성
- 테스트·정확도·신뢰성·성능 측정 계획 작성
- 브랜치와 Conventional Commits 규칙 작성

## Decisions

1. 토스페이먼츠는 전체 소비내역 제공자가 아니라 선택적인 상점 결제 웹훅 Adapter로 표현한다.
2. 운영용 오픈뱅킹 연동은 MVP에서 제외하고 확장 Port만 고려한다.
3. LLM은 구조화에 사용하고 Risk 판정은 결정론적 규칙으로 분리한다.
4. PostgreSQL이 금융 원장과 동시성의 최종 기준이다.
5. Kafka는 at-least-once 재전달을 전제로 Consumer 멱등성을 구현한다.
6. 프론트는 백엔드 2주 완료 후 1주 동안 Next.js로 개발한다.
