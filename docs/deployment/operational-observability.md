# 운영 로그와 모니터링

운영 장애를 사용자의 신고 이후에만 발견하지 않도록 애플리케이션 상태와 핵심 이벤트 처리 흐름을 수집한다. Prometheus는 백엔드의 전용 관리 포트에서 15초마다 지표를 수집하고, Grafana는 운영자가 바로 확인할 수 있는 대시보드를 제공한다.

## 접근 경계

Prometheus와 백엔드 관리 포트는 외부 통신이 차단된 `monitoring` 네트워크에만 둔다. Grafana의 3001 포트는 서버의 `127.0.0.1`에만 연결하므로 인터넷에서 직접 접근할 수 없다.

운영자는 SSH 터널을 연 뒤 로컬 브라우저에서 접속한다.

```bash
ssh -L 3001:127.0.0.1:3001 operator@server
```

터널이 연결된 동안 `http://localhost:3001`에서 Grafana를 확인한다. 로그인 정보는 `deploy/.env`의 `GRAFANA_ADMIN_USER`, `GRAFANA_ADMIN_PASSWORD`를 사용한다. 익명 접근과 사용자 임의 가입은 비활성화한다.

## 확인 지표

기본 대시보드는 다음 신호를 한 화면에 표시한다.

- 백엔드 수집 대상의 정상 여부
- URI별 HTTP 요청량과 p95 응답 시간
- 최근 5분간 HTTP 5xx 비율
- Outbox 발행 성공·실패 건수
- JVM heap 사용률

소비 분석 Consumer는 성공·실패 건수와 처리 시간을 별도로 기록한다. 요청과 응답에는 `X-Request-ID`를 포함하며, 안전한 형식의 클라이언트 식별자는 유지하고 잘못된 값은 서버 UUID로 교체한다. 같은 값이 구조화 로그의 `requestId`에 들어가 화면 오류와 서버 로그를 연결할 수 있다.

## 경보 규칙

다음 상태를 Prometheus 경보로 판정한다.

- 백엔드 수집 대상이 1분 이상 응답하지 않음
- 5분간 HTTP 5xx 비율이 5%를 초과한 상태가 5분 지속됨
- 최근 5분 동안 Outbox 발행 실패 발생
- 최근 5분 동안 소비 분석 메시지 실패 발생
- JVM heap 사용률이 85%를 넘은 상태가 10분 지속됨

현재 단계에서는 경보 판정과 대시보드 표시까지만 제공한다. 이메일·메신저 알림은 호스팅 환경을 정한 뒤 Alertmanager 또는 관리형 모니터링의 알림 채널과 연결한다.

## 로그 보관

운영 profile의 백엔드는 콘솔 로그를 JSON으로 기록한다. 모든 컨테이너는 Docker `json-file` 로그를 파일당 10MB, 최대 5개로 순환해 단일 서버의 디스크 고갈을 막는다.

```bash
docker compose --env-file deploy/.env -f deploy/compose.production.yml logs --since 30m backend
```

이 설정은 단일 서버의 최근 장애 조사 범위를 위한 것이다. 장기 검색과 서버 장애 이후 로그 보존이 필요하면 외부 로그 저장소를 연결한다. 인증 토큰, 금융 원문과 비밀번호는 로그에 남기지 않는다.
