# 💳 Spending Guard - 소비 변화 감지 및 예산 관리 서비스

## 💡 Spending Guard는 어떤 서비스인가요?

카드나 계좌 알림은 자주 확인해도 이번 달에 어디에서 평소보다 많이 썼는지 바로 알아보기 어렵습니다. 특히 배달비, 택시비, 쇼핑처럼 매달 금액이 달라지는 지출은 예산을 많이 사용한 뒤에야 체감하는 경우가 많습니다.

**Spending Guard**는 금융 알림 텍스트를 소비 내역으로 정리하고, 월간 예산과 소비 흐름을 함께 보여주는 개인 소비 관리 서비스입니다. 사용자가 지출 변화를 조금 더 일찍 알아차리고 필요한 소비인지 스스로 판단할 수 있도록 돕는 것을 목표로 합니다.

위험한 소비라고 단정하기보다는 확인이 필요한 이유를 함께 안내하고, 잘못 분류된 내역은 사용자가 직접 수정할 수 있도록 개발합니다.

## 🛠️ 주요 기능

### 소비 내역 간편 등록

- 카드·은행 알림 텍스트를 붙여 넣으면 금액, 가맹점, 거래 시각과 유형을 자동으로 정리합니다.
- 같은 알림이 여러 번 들어오더라도 소비 금액이 중복 반영되지 않도록 처리합니다.
- 이후에는 CSV와 결제 테스트 연동을 추가해 입력 과정을 줄일 예정입니다.

### 예산 및 소비 현황 관리

- 월간 예산과 카테고리별 예산을 설정하고 남은 금액을 확인할 수 있습니다.
- 승인뿐 아니라 취소와 환불도 반영해 실제 소비 금액에 가까운 현황을 제공합니다.
- 사용자가 소비 카테고리를 수정하면 예산과 통계도 다시 계산합니다.

### 소비 변화와 위험 신호 안내

- 평소보다 빠르게 늘어난 지출과 반복 결제 금액의 변화를 감지합니다.
- 중복 결제 의심, 심야 시간대의 큰 지출 등 확인이 필요한 소비를 알려줍니다.
- 단순한 경고로 끝내지 않고 어떤 기준으로 감지되었는지 이유를 함께 보여줍니다.

## ⚙️ 소비 내역 처리 방식

```text
금융 알림 수집 → 원문 저장 → 소비 정보 분석 → 예산 반영 → 위험 신호 안내
```

알림 수집과 분석 작업을 분리해 분석이 늦어지거나 실패하더라도 원본 내역은 잃지 않도록 설계했습니다. 소비 금액은 PostgreSQL 트랜잭션과 중복 처리 방지 규칙으로 일관성을 유지하고, 시간이 오래 걸리는 분석은 Kafka를 통해 비동기로 처리할 예정입니다.

## 🚧 현재 진행 상황

소비 이벤트 처리 흐름, 데이터 모델, API 계약을 설계했고 백엔드 실행 환경과 서비스 상태 확인 API를 구성했습니다. 기능 구현과 검증이 끝날 때마다 이 문서에 실제 사용할 수 있는 기능과 실행 방법을 추가합니다.
